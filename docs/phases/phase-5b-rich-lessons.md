## Goal

Lessons that read like the owner's hand-made HTML notes: numbered sections with a sidebar, practice quizzes, code with file names, step flows, callouts, tables and "Try it" simulators. Built once, so **every new course needs content only, no code**. The content can be written by hand or generated by Claude.

## Approach (Option C, hybrid)

| Part | Choice | Why |
| --- | --- | --- |
| Text | Markdown + 5 blocks in standard `remark-directive` syntax (`:::quiz` …) | Writers and AI already know Markdown. The frontend uses a well-known library instead of a custom parser. Stored as text in `Lesson.content`, so the schema didn't change. |
| Simulators | Self-contained HTML files, run in a sandboxed iframe | Any interactivity, with no per-course frontend code, isolated from the site. |
| Validation | One pure parser shared by the importer, the admin editor and a CLI | A broken lesson never reaches students, and every error has a line number. |

## Edge cases handled (each has a test)

**Structure.** The checker reports:
- unclosed blocks (at the line they opened), a stray `:::`, unknown blocks (no cascade of follow-up errors), and nesting (names both lines)
- `::::` instead of `:::`, broken `{attrs}`, duplicate attributes, attribute typos per block (`typ=`), headings inside blocks
- `# ` H1, empty headings, more than 40 sections

It also handles:
- duplicate section titles (unique ids `-2`, `-3`)
- non-Latin titles (safe id)
- italic subtitles only when the whole line is italic
- indented blocks inside lists
- CRLF and BOM giving the same line numbers

**Code.** `:::`, headings and `<script>` inside code are ignored. `~~~` fences work, and so do longer fences wrapping ```` ``` ````. A shorter fence or a different fence character doesn't close a block. An unclosed fence is reported where it starts. Inline ```` ```x``` ```` is not treated as a fence. Only `title=` is allowed in the info string, and it needs a value and a length limit. Unknown or missing languages are warnings.

**Quiz.** Rules enforced:
- a question is required, with 2–6 options, at least one right and one wrong
- no empty or duplicate options (case-insensitive)
- options come before the explanation
- no stray text after the options
- code in a quiz goes only in the question

A quote inside the question and multi-line explanations are fine. A one-option quiz gets one error, not two.

**Answer leak.** A practice quiz (answers visible in the page) that copies a graded module-quiz question is blocked in the importer, on lesson save and on quiz save. Matching ignores case, spacing and Markdown marks.

**Widgets and images.** Sources must be in `assets/` (no URLs, `..` or other folders) with the right file type. Widget height and widget count are limited.

The editor accepts only uploaded `beyownd-asset:` references, and they must exist in storage. Images may be `https://` or `assets/`. `http://`, `data:` and `javascript:` are errors, and missing alt text is a warning.

**HTML.** `<script>`, `<iframe>`, `<style>` and event handlers are errors. Other tags are warnings. HTML inside backticks and `a < b` comparisons are fine. One-line comments are allowed.

**Uploads.** Magic bytes must match the extension (HTML renamed `.png` is rejected). For SVGs, `<script>`, `<foreignObject>`, `on*=`, external `href` and `<!ENTITY` are rejected. Widgets are rejected if they load scripts, CSS or images from the internet, if they aren't UTF-8, or if they're over 300 KB. Images over 2 MB get a 413. Empty bodies, JSON bodies and a missing filename are rejected. Only admins can upload. The same bytes always give the same name.

**Import.** The importer handles:
- every error across all lessons listed in one run
- assets read once even when many lessons use them
- symlinks pointing outside the course folder are refused
- **filename case must match exactly** (Windows ignores case, the Linux server doesn't)
- prose mentioning `assets/x.png` is not rewritten, and a path that's a prefix of another isn't half-replaced
- assets written before the transaction (content-addressed, so a failed transaction leaves only an unused file)
- re-import is byte-identical

**Compatibility.** Old lessons (saved before the format) can still be renamed. Only a content change triggers the new rules, and delivery never fails on old content.

**Body size.** A full 50,000-character Hindi lesson is ~140 KB of UTF-8, more than the global 100 KB JSON limit. `/api/admin` gets 512 KB.

## Security model for widgets

`GET /api/assets/<hash>.html` responds with:

```
Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline';
  style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src 'none';
  form-action 'none'; frame-ancestors <frontend origins>
Cross-Origin-Resource-Policy: cross-origin    (helmet default would block the frontend)
X-Frame-Options: (removed - frame-ancestors replaces it)
X-Content-Type-Options: nosniff
Cache-Control: public, max-age=31536000, immutable
```

- **The CSP `sandbox` directive gives the document an opaque origin even if someone opens the URL directly.** The widget can't read our cookies or call our API with the user's session.
- On top of that, the frontend iframe uses `sandbox="allow-scripts"` without `allow-same-origin`.
- **Assets are public by unguessable name** (64-bit hash). Lesson text stays behind enrollment. Acceptable for images and simulators; documented.
